# ADR 0002 — Testing and Coverage Observation

Date: 2025-09-03

Status: Proposed

## Context

During routine verification we inspected the Vitest coverage report to identify remaining uncovered lines that prevent the repository from meeting its configured coverage thresholds.

## Observation

- File: `src/index.js`
- Coverage summary (from coverage/lcov-report generated by Vitest):
  - Statements: 78.57% (11/14)
  - Branches: 66.66% (2/3)
  - Functions: 100% (2/2)
  - Lines: 78.57% (11/14)

- The uncovered code is localized to the top-level CLI invocation in `src/index.js`:

```js
if (process.argv[1] && process.argv[1].endsWith('src/index.js')) {
  // When run directly (node ./src/index.js), execute the CLI entrypoint
  runCli();
}
```

This branch is not executed by existing tests because it only runs when the module is evaluated as a top-level script (i.e., `node ./src/index.js`). Normal imports or in-process invocations that call `runCli()` do not exercise this path.

## Decision / Next steps

To raise coverage to meet the configured thresholds, add a single targeted test that forces top-level evaluation of `src/index.js` in a way that V8 coverage records it. Recommended approaches (choose one):

1. In-process deterministic evaluation
   - Use the existing test helper `importFreshAsScript` (from `test/utils/cli.js`) to import the module as a script while setting `process.argv[1]` to the resolved path of `src/index.js`.
   - Use `installConsoleLogSpy` to observe console output and assert the expected message.
   - This approach records coverage in the same process and is the preferred option for speed and determinism.

2. Spawn a separate Node process
   - Use `child_process.spawnSync` to run `node -e "import('file://'+path)"` or `node ./src/index.js`.
   - Capture stdout and assert the expected output. This is slightly heavier but isolates the evaluation.

The minimal test should:

- Set `process.argv[1]` (in the test process or the imported script process) to the module path so the `endsWith('src/index.js')` check passes.
- Ensure the module is imported/evaluated fresh (no cache) so the top-level branch runs.
- Assert that `Hello, World!` is printed (via console spy or captured stdout).

## Rationale

- Keeping the change minimal and well-scoped avoids touching production code and ensures the coverage gap is closed by adding a test only.
- Using the shared test helpers already present keeps tests consistent and avoids duplication.

## Status after inspection

The uncovered lines have been documented here. The next actionable change is to add the minimal test described above (not performed in this ADR).
